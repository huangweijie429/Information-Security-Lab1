5. CVE-2021-41773 reproduction

Target: path traversal in Apache HTTP Server 2.4.49, which also enables CGI command execution with the right configuration. The environment (work1-cve/Dockerfile) mirrors the Vulhub setup: mod_cgi and ScriptAlias enabled, and <Directory /> set to Require all granted.

RequestVulnerable 2.4.49Fixed 2.4.51
GET /cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd HTTP 200, returns root:x:0:0:root:/root:/bin/bash HTTP 400, no file content
POST …/bin/sh with body echo Content-Type: text/plain; echo; id HTTP 200, uid=1(daemon) gid=1(daemon) HTTP 400, no output
GET /cgi-bin/hello.sh (regression) 200 hello from cgi 200 hello from cgi (functionality intact)

Full commands and outputs: work1-cve/evidence/01–05-*.txt.

6. Root cause

Apache 2.4.49 rewrote path normalisation (ap_normalize_path). The new code only expanded %2e segments for paths that start inside the document root and did not reject .. sequences that escape it. A request such as /.%2e/.%2e/… was therefore normalised into ../../.. after the authorisation check but before the file lookup, bypassing access control. Two configuration choices turn file disclosure into code execution:

  1. <Directory /> grants access to the whole filesystem, so the escaped path passes authorisation;
  2. mod_cgi and ScriptAlias are enabled, so a traversed executable is run with the request body as input.

The defect class is therefore improper input handling (incomplete canonicalisation of a user-controlled path), not a memory-safety bug.

7. Fix and verification

LayerChangeWhy it works
Patchimage upgraded httpd:2.4.49 → 2.4.51 2.4.51 rejects any normalised path that escapes the document root and also blocks the double-encoded %252e bypass of 2.4.50
Hardening<Directory /> changed to Require all denied; CGI restricted to cgi-bin removes the second precondition: even if a future normalisation bug appears, a traversed path cannot be authorised

After the fix the same PoC returns 400, while the home page and legitimate CGI still work (regression passed). poc.sh verifies any instance in one command: exit code 1 for the vulnerable build, 0 for the fixed one.

8. Conclusion

Parameterized queries, output escaping and strong authentication push application-level injection and script execution risks very low, but they cannot stop defects in the infrastructure itself. This CVE teaches two lessons at once: patch promptly (remove the known defect), and apply least privilege (even without the patch, the impact drops from RCE to a 403). Together they are what makes a regression test able to prove both "the attack fails" and "the feature still works".
